# Glossary — one term per concept

This is the canonical list. UI copy, Help and the docs use **only** the term in the first
column. Retired terms are flagged so the brand lint and reviews can catch them. The IA
conflicts this resolves are in `../ia/navigation.md` §5.

| Term (use) | Definition | Retired / avoid |
|---|---|---|
| **Your work** | The ranked list of things that need you (or everyone, with the scope switch) | Front page, the tables in force |
| **Library** | Reviewed reference documents that requirement work can cite | Table 1 |
| **Document** | One policy or reference item in the library, with its versions | Source (in the library) |
| **Version** | One uploaded file of a document (version 1, 2…) | Edition, revision |
| **In service** | The published version requirement work cites now; also the catalogue version requirement work maps against now | In force, active (in UI), edition in force |
| **Passage** | One reviewed unit of a document's text that can be cited | Chunk, block, field |
| **Review** | Deciding passages (keep, edit, exclude) or deciding suggestions | Galley |
| **Seen** | A passage or suggestion that stayed the current one for a moment (about 0.6 s) in this review; passing through doesn't count (GATE 8.2) | — |
| **Flagged** | Has a warning from reading | — |
| **Blocks approval** | A warning that must be resolved (exclude the passage, or upload a new version) | Blocking warning |
| **Approve and publish** | Make a reviewed version citable | — |
| **Withdraw** | Stop requirement work citing a document | Retire (for documents) |
| **Return to service** | Make a withdrawn document citable again | (re-)approve |
| **Search index for tables** | An optional second index that keeps table rows together | Table-aware version, search version |
| **Cited by** | The requirements that cite a document (only those you can see) | Citations (as a tab), dependants, who cites it |
| **Catalogue** | The architecture catalogue: systems, connections, areas, offerings, journeys, channels | Table 2, architecture knowledge |
| **Catalogue version** | One named state of the catalogue | Release (in UI), edition |
| **Draft** | A catalogue version being prepared, not yet published | Galley proof, working copy |
| **Replaced version** | A published catalogue version that is no longer in service | Superseded, old edition |
| **Put back in service** | Make a replaced catalogue version the one in service again | Activate, roll back |
| **Sources** | The documents and catalogue file a draft is read from (step 1) | Suggestions page |
| **Suggestion** | A change the model proposed from a source, waiting for a person | Candidate, proposal |
| **Suggested** | The mark on anything a model proposed and nobody has decided | AI, auto |
| **Stated / inferred** | Whether the source says it outright or the model inferred it | Basis |
| **Evidence** | The source passage a suggestion cites, with the quoted line | Chunk |
| **Changes** | Everything a draft would change against the version in service | Diff, alterations |
| **Check** | Building the draft for matching and comparing sample requirements | Samples |
| **Mapping impact** | How requirement work's mappings would differ under a version | — |
| **System** | A software system in the catalogue | Application |
| **Connection** | A dependency between two systems, said as a sentence | Relationship, dependency (in UI) |
| **Capability area** / **Landscape area** | The two ways systems are grouped | Domain, capability domain, landscape domain |
| **Offering** | A product offering with its order types, components and journeys | Product (in the catalogue) |
| **Journey** | The steps through systems for one offering, order type and channel | Timetable |
| **Ownership** | Who runs each system: squads, value streams, products, people | Squad catalogue, Table 3 |
| **Squad** | A team that runs systems | — |
| **Contact** | The person in a squad to ask about a system | — |
| **Gap** | A system in service with no squad, or no contact | Due row |
| **Re-confirmation** | Confirming that a document or system is still right, when due | Review (for this), reminder, reviews due |
| **Requirements** | Requirement knowledge held by requirement work: requirements, findings, historic requirements | Table 4, corpus (in UI) |
| **Finding** | A possible duplicate or contradiction between requirements | — |
| **Historic requirement** | A past requirement imported from BRDs to inform new work | — |
| **Job** | Background work: reading, indexing, building, checking | Task, process |
| **Jobs** | The panel listing running, failed and recent jobs | — |
| **Needs attention** | A failed job or blocked item that a person must act on | Disruption, delayed, failure (as a label) |
| **Explorer** | The read-only view of the catalogue in service, open to anyone signed in | — |
| **Knowledge admin** | The role that may curate (written as words, never `knowledge_admin`) | `knowledge_admin` (in UI) |
| **Requirement AI** | requirement-portal's product name | Requirement portal (in UI) |
